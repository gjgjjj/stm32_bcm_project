## 1 概述
### 1.1 设计目标
本软件基于STM32F103ZET6硬件平台与FreeRTOS实时操作系统，实现车身控制器核心功能，包含灯光控制、门锁控制、环境光采集与自动灯光、CAN总线通信、故障诊断与掉电存储、人机交互等模块。设计严格遵循分层解耦、模块化、高内聚低耦合原则，满足车载ECU工程化开发规范，保障系统实时性、可靠性与可扩展性。

### 1.2 设计原则
1. **分层解耦原则**：驱动层、服务层、应用层严格分离，层间仅通过标准接口调用，禁止跨层直接操作硬件。
2. **实时性原则**：高优先级任务优先调度，关键通信与故障检测任务保障低延迟，周期报文时序满足协议容差要求。
3. **可靠性原则**：故障防抖、资源互斥、总线异常恢复、看门狗防护多重机制，避免单点异常导致系统失效。
4. **可扩展性原则**：模块接口标准化，预留功能扩展空间，新增业务不改动底层驱动与核心框架。
5. **优先级仲裁原则**：控制逻辑严格遵循 `远程CAN指令 > 本地手动按键 > 自动灯光逻辑` 的优先级规则，冲突时自动丢弃低优先级指令。

## 2 整体软件架构
### 2.1 三层软件架构
系统采用标准三层架构，各层职责单一，依赖关系自上而下，底层不依赖上层业务。

| 层级 | 核心职责 | 包含模块 | 依赖关系 |
| ---- | ---- | ---- | ---- |
| 应用层 | 业务逻辑编排，实现BCM核心控制策略 | 灯光管理、门锁管理、迎宾灯光、系统状态管理、故障联动 | 仅调用服务层接口，不直接操作硬件 |
| 服务层 | 通用基础能力封装，提供与业务无关的通用组件 | 按键管理、信号滤波、故障管理、CAN协议解析、存储管理、日志服务 | 仅调用驱动层接口，不包含具体业务规则 |
| 驱动层 | 硬件外设抽象封装，提供统一硬件读写接口 | GPIO、ADC、CAN、UART、SPI Flash、RTC、IWDG | 直接操作STM32 HAL库与外设寄存器，无上层依赖 |

### 2.2 FreeRTOS系统调度架构
基于FreeRTOS抢占式多任务调度机制，按业务实时性要求划分任务优先级，通过消息队列、软件定时器、互斥锁实现任务间通信与资源保护。
- **高优先级**：CAN通信任务、故障检测任务，保障指令响应与故障上报实时性
- **中优先级**：传感器采集任务、按键检测任务
- **低优先级**：执行器输出任务、人机交互任务、日志存储任务
- **系统级**：软件定时器驱动心跳周期报文，保证时序精度不受任务阻塞影响

## 3 驱动层详细设计
驱动层所有模块仅做硬件封装，无业务逻辑，接口标准化，可单独单元测试，引脚定义与参数严格对齐《硬件资源分配与接口说明》。

| 模块文件 | 对应硬件 | 核心接口函数 | 设计说明 |
| ---- | ---- | ---- | ---- |
| bsp_gpio.c/h | 继电器输出、按键输入、触点回读、RGB灯、蜂鸣器 | `GPIO_ReadPin()`<br>`GPIO_WritePin()`<br>`GPIO_TogglePin()` | 引脚宏定义与硬件文档一一对应；上电默认状态严格遵循故障安全要求，继电器默认断开 |
| bsp_adc.c/h | ADC1_IN1（PA1）光照电位器 | `ADC_GetSingleValue()`<br>`ADC_GetAverageValue()` | 12位分辨率单通道软件触发采样，内置多次采样均值接口，供上层滤波算法调用 |
| bsp_can.c/h | CAN1（PB8_RX、PB9_TX） | `CAN_SendStdFrame()`<br>`CAN_GetRxMessage()`<br>`CAN_GetErrorStatus()` | 250Kbps标准帧，采样点80%；封装标准帧收发接口，提供错误状态读取；接收采用中断+缓存机制；开启引脚重映射与AFIO时钟 |
| bsp_uart.c/h | USART1（PA9_TX、PA10_RX） | `UART_SendString()`<br>`UART_Printf()` | 波特率115200，8数据位无校验1停止位；实现分级日志输出，支持全局开关 |
| bsp_flash.c/h | SPI1 W25Q64 Flash | `Flash_Read()`<br>`Flash_Write()`<br>`Flash_EraseSector()` | CPOL=0/CPHA=0全双工主模式；封装基础读写擦除接口，上层存储管理负责逻辑地址映射 |
| bsp_rtc.c/h | RTC实时时钟 | `RTC_GetTimeStamp()`<br>`RTC_SetTime()` | 外部LSE 32.768KHz时钟源，24小时制；提供秒级时间戳，用于故障记录时间标注 |
| bsp_iwdg.c/h | 独立看门狗 | `IWDG_Init()`<br>`IWDG_Feed()` | 预分频系数64，溢出时间约1.5s；系统任务中定期喂狗，异常时自动复位 |

## 4 服务层详细设计
### 4.1 按键管理模块
- **功能**：实现两路独立按键的状态机扫描、软件防抖、长短按识别
- **防抖参数**：消抖时间20ms，长按判定阈值1000ms
- **事件输出**：短按事件、长按事件
- **对应按键逻辑**：
  - KEY1（PA0）：短按触发近光灯开关切换，长按触发灯光工作模式（手动/自动）切换
  - KEY2（PC13）：短按触发门锁上锁/解锁切换，长按触发全部历史存储故障清除
- **接口方式**：提供事件回调注册，上层业务通过回调获取按键动作，与硬件完全解耦

### 4.2 信号滤波模块
- **ADC滑动均值滤波**：采用滑动窗口滤波平滑光照传感器原始采样值，消除瞬时噪声
- **光照滞回判定**：设置双阈值滞回区间，避免临界点光线波动造成状态频繁跳变
  - 黑夜判定：ADC值 < 1600
  - 白天判定：ADC值 > 2800
  - 中间区间：保持上一次判定结果
- **超量程校验**：ADC值超出合法范围时判定为传感器异常，保持上一有效状态

### 4.3 故障管理模块
- **故障码定义**：与CAN协议完全对齐
  - 0x01：传感器异常
  - 0x02：CAN总线异常
  - 0x03：车灯故障
  - 0x04：车锁故障
- **故障防抖机制**：所有故障均需异常条件持续满足防抖时间后才确认激活，瞬时波动不触发故障
- **故障状态管理**：维护当前激活故障位图、历史故障链表，支持故障产生、消除事件通知
- **故障分级策略**：
  - 轻微故障：传感器异常，系统保持正常运行，红灯闪烁提示
  - 严重故障：CAN总线离线、执行器回读故障，触发故障模式

### 4.4 CAN协议解析模块
严格遵循《CAN通信协议规范》实现，无额外自定义报文。
- **接收处理**：
  1. 校验报文DLC长度，非法长度直接丢弃
  2. 校验信号值有效范围，非法值丢弃报文
  3. 指令间隔防抖：灯光/门锁指令最小间隔100ms，故障清除指令最小间隔500ms
  4. 解析后通过消息队列投递至应用层对应业务模块
- **发送处理**：
  1. 严格按照信号布局表组包，多字节信号采用Intel小端字节序
  2. 支持周期发送、事件触发发送两种模式
  3. 故障报文发送队列：多条故障排队发送，帧间最小间隔10ms，避免总线拥堵
- **优先级规则**：CAN远程指令优先级高于本地按键，冲突时丢弃低优先级指令

### 4.5 存储管理模块
- **存储介质**：W25Q64 SPI Flash
- **存储方案**：环形缓冲区存储故障日志，自动覆盖最早记录，均衡Flash擦写寿命
- **记录结构**：每条故障记录包含故障码、故障类型（产生/消除）、RTC时间戳、校验字节
- **核心功能**：故障记录写入、批量读取、全部清除、上电历史故障加载
- **可靠性**：记录末尾增加校验和，读取时校验数据有效性，损坏记录自动丢弃

### 4.6 日志服务模块
- **日志分级**：DEBUG、INFO、ERROR三级，可通过宏全局开关输出等级
- **输出格式**：统一格式 `[时间戳] [等级] [模块名] 日志内容`
- **输出通道**：USART1串口输出，支持故障日志串口查询打印

## 5 应用层详细设计
### 5.1 灯光管理模块
- **工作模式**：支持手动模式、自动模式，KEY1长按切换
- **手动模式**：灯光状态仅响应CAN远程指令、本地KEY1短按
- **自动模式**：根据光照滞回判定结果自动开关灯；同时保留手动/CAN指令接管能力，指令优先级高于自动逻辑
- **执行校验**：每次输出控制后，延时稳定时间读取触点回读引脚（PC4），校验继电器实际状态；指令目标与回读状态不一致且持续防抖时间后，触发车灯故障（故障码0x03）
- **状态上报**：灯光状态发生变化时，触发车灯状态报文（ID:0x031）CAN上报
- **回读防抖**：触点回读信号软件防抖15ms

### 5.2 门锁管理模块
- **控制源**：响应CAN远程指令、本地KEY2短按，实现上锁/解锁切换
- **执行校验**：动作执行后读取触点回读引脚（PC3）校验，不一致且持续防抖后触发车锁故障（故障码0x04）
- **状态上报**：门锁状态变化时，触发门锁状态报文（ID:0x041）CAN上报
- **联动逻辑**：解锁事件触发迎宾灯光逻辑判断
- **回读防抖**：触点回读信号软件防抖15ms

### 5.3 迎宾灯光模块
- **触发条件**：门锁状态由上锁切换为解锁，且当前光照判定为黑夜
- **执行逻辑**：自动点亮近光灯，启动迎宾计时
- **优先级规则**：迎宾期间，手动按键、CAN指令可直接接管灯光控制权
- **结束逻辑**：计时结束后，恢复原灯光工作模式与自动灯光逻辑；迎宾计时期间不受门锁再次上锁影响

### 5.4 系统状态管理模块
- **模式管理**：维护系统两种运行模式
  - 正常模式：所有功能正常运行，RGB绿灯常亮
  - 故障安全模式：执行器全部断开，严重故障声光报警，保留本地按键与故障清除功能
- **上电自检**：上电依次完成时钟、GPIO、ADC、CAN、串口、Flash外设自检；自检失败直接进入故障安全模式
- **心跳管理**：周期上报设备心跳报文（ID:0x020），报文中携带当前系统工作模式
- **故障联动**：严重故障产生时自动切入故障安全模式；所有严重故障消除后恢复正常模式

## 6 FreeRTOS任务与调度设计
### 6.1 任务总表
按实时性要求从高到低分配优先级，数值越大优先级越高。

| 任务名称 | 任务优先级 | 栈大小 | 运行周期/触发方式 | 核心职责 |
| ---- | ---- | ---- | ---- | ---- |
| CAN接收处理任务 | 5（最高） | 256 Byte | 消息队列阻塞等待 | 读取CAN接收队列，完成协议校验解析，分发至对应业务模块 |
| 故障检测任务 | 4 | 256 Byte | 10ms 轮询 | 传感器异常检测、执行器回读校验、CAN总线状态监测、故障防抖计数 |
| 传感器与按键任务 | 3 | 256 Byte | 10ms 轮询 | ADC光照采集、按键扫描、光照状态判定 |
| 执行器控制任务 | 2 | 256 Byte | 事件触发 + 20ms 轮询 | 继电器输出控制、状态变更检测、事件报文触发 |
| 人机交互任务 | 1（最低） | 128 Byte | 50ms 轮询 | RGB指示灯、蜂鸣器报警节奏刷新 |
| 日志存储任务 | 1 | 256 Byte | 事件触发 | 故障日志写入Flash、串口日志输出 |

### 6.2 软件定时器配置
周期报文由FreeRTOS软件定时器驱动，不受任务阻塞影响，保障时序容差指标。

| 定时器名称 | 周期 | 回调函数职责 | 容差要求 |
| ---- | ---- | ---- | ---- |
| 心跳报文定时器 | 2000ms | 组包并发送设备心跳报文 | ±80ms |

### 6.3 任务间通信机制
1. **消息队列**
   - CAN接收队列：CAN中断投递原始报文，接收任务读取解析
   - 指令队列：解析后的控制指令投递至执行器任务
   - 故障事件队列：故障检测模块投递故障事件，触发上报与存储
2. **互斥锁**
   - 全局状态互斥锁：保护系统工作模式、故障状态等共享资源
   - Flash操作互斥锁：保护SPI总线并发访问
3. **访问规则**：多任务共享变量必须通过临界区或互斥锁保护，禁止无保护并发读写

### 6.4 时序指标保障
严格匹配CAN通信协议时序规范：
- 状态变化事件报文：状态变更后 ≤20ms 完成发送
- 故障确认后报文：故障防抖确认后 ≤50ms 完成上报
- 指令响应：指令接收解析 ≤5ms，指令执行完成 ≤50ms，状态反馈 ≤100ms

## 7 核心业务流程
### 7.1 上电启动流程
1. 系统复位，HAL库初始化，系统时钟配置为72MHz
2. 外设驱动依次初始化：GPIO、ADC、CAN、UART、SPI、RTC、IWDG
3. FreeRTOS内核初始化，创建所有任务、队列、定时器、互斥锁
4. 加载Flash历史故障记录，初始化故障管理模块
5. 启动系统调度器，任务开始运行
6. 完成上电自检，自检通过进入正常模式；失败进入故障安全模式
7. 存在历史故障则上电首次上报故障状态报文

### 7.2 CAN控制指令处理流程
1. CAN外设收到报文，触发接收中断，将原始帧写入CAN接收队列
2. CAN接收任务被唤醒，读取报文并执行协议校验
3. 校验不通过：直接丢弃，记录错误日志
4. 校验通过：解析指令内容，投递至执行器控制任务
5. 执行器任务进行优先级仲裁，高优先级指令覆盖当前低优先级动作
6. 更新继电器输出电平，延时稳定后读取触点回读，校验执行结果
7. 状态发生变化时，触发对应状态报文上报；校验失败则触发故障上报

### 7.3 故障检测与处理流程
1. 故障检测任务周期轮询各异常条件
2. 异常条件触发时启动防抖计时，瞬时抖动自动清零
3. 持续异常达到防抖时间，确认故障激活
   - 更新故障状态位图
   - 投递故障事件，触发CAN故障报文（ID:0x003）上报
   - 写入Flash故障日志
   - 根据故障等级执行对应安全策略与报警
4. 异常条件消失，启动恢复防抖计时
5. 持续正常达到恢复时间，确认故障消除
   - 更新故障状态位图
   - 上报故障消除报文
   - 所有严重故障消除后，退出故障安全模式

### 7.4 自动灯光与迎宾灯光流程
1. 传感器任务周期采集光照ADC值，经滑动滤波后输出有效值
2. 滞回比较算法判定昼夜状态，状态变更时更新全局光照标志
3. 灯光管理模块判断当前模式：
   - 手动模式：不执行自动开关灯逻辑
   - 自动模式：根据昼夜状态自动切换灯光
4. 门锁解锁事件触发时：
   - 判定当前为黑夜则启动迎宾灯光，点亮车灯
   - 启动迎宾软件定时器，计时期间暂停自动灯光逻辑
   - 计时结束后恢复原灯光模式与自动控制逻辑

## 8 异常与可靠性设计
### 8.1 故障安全状态
系统进入故障安全模式时，强制执行以下状态：
- 所有继电器输出低电平，负载全部断开
- RGB红灯常亮，绿灯强制熄灭
- 蜂鸣器按严重故障节奏报警
- 保留本地按键功能与故障清除能力
- 周期心跳报文继续发送，工作状态字段更新为故障模式（0x01）

### 8.2 CAN总线异常处理
严格对齐CAN协议规范定义的三级错误状态与恢复流程：
- **主动错误状态**：TEC<127且REC<127，正常通信，无额外处理
- **被动错误状态**：TEC≥127或REC≥127，记录轻微故障，继续通信
- **总线关闭（Bus‑Off）**：
  1. 记录CAN总线严重故障（故障码0x02），执行器切入安全状态
  2. 尝试发送故障状态报文；总线无法发送时存入本地故障缓存
  3. 延时100ms后完整重新初始化bxCAN外设，清除错误计数器
  4. 初始化成功后恢复通信，上报故障消除报文
  5. 最多连续重试3次，失败则保持故障安全模式，等待系统复位

### 8.3 看门狗防护
- 独立看门狗溢出时间约1.5s，由系统状态任务统一喂狗
- 任务卡死、程序跑飞、硬fault等异常场景触发看门狗自动复位
- 复位后系统记录看门狗复位事件，便于问题追溯

### 8.4 数据可靠性
- Flash故障记录增加校验和，读取时校验完整性
- 全局共享资源全部加锁保护，避免多任务并发读写错乱
- 指令与故障均采用防抖机制，滤除瞬时干扰与误触发
