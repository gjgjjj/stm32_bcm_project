## 1 文档说明

### 1.1 文档目的

本文档定义该模拟BCM车身控制器CAN通信协议的完整规范，包含物理层参数、报文定义、信号布局、通信时序与总线异常处理机制。所有CAN相关驱动开发、协议解析、上位机调试均以此文档为唯一依据。

### 1.2 适用范围

本文档适用于以下开发与调试场景：
- BCM固件中CAN驱动层、协议解析层代码开发
- CAN调试上位机的DBC文件制作与报文解析
- 系统集成测试中CAN通信功能验证


## 2 物理层与链路层参数

### 2.1 总线基本参数

| 参数名称 | 配置值 | 说明 |
| ---- | ---- | ---- |
| 总线协议 | CAN 2.0A | 支持标准帧（11位ID）|
| 通信速率 | 250 Kbps | 适配中低速车身控制网络 |
| 采样点 | 87.5% | 保证总线信号采样的稳定性 |
| 同步跳转宽度 | 1 Tq | 位时序配置，用于时钟偏差补偿 |

### 2.2 收发器配置

| 参数名称 | 配置值 | 说明 |
| ---- | ---- | ---- |
| 收发器型号 | SIT1042 | 板载CAN收发器芯片 |
| 对应MCU引脚 | PB8 (CAN_RX)、PB9 (CAN_TX) | 需开启CAN1引脚重映射与AFIO时钟 |
| 工作模式 | 正常模式 | 不支持低功耗休眠模式 |

### 2.3 帧格式

本项目所有报文均采用**CAN 2.0A标准帧格式（11位ID）**。数据长度码（DLC）根据各报文实际信号长度定义，未使用字节填充0x00。


## 3 报文ID分配方案

### 3.1 ID编码规则

11位标准帧ID采用功能域划分方式编码，保障ID唯一性，避免总线仲裁冲突。

| 位段 | 位宽 | 编码含义 |
| ---- | ---- | ---- |
| Bit10 - Bit8 | 3位 | 0：高优先级（故障报文 + 外部控制指令） 1：低优先级（BCM 周期 / 状态上报报文） |
| Bit7 - Bit5 | 3位 | 功能域：0=系统状态，1=灯光，2=门锁，3=故障诊断 |
| Bit4 - Bit0 | 5位 | 同功能域内报文序号|

| 车灯状态报文 | 0x031 | BCM上报 | 灯光 | BCM | 上位机 |
| 门锁状态报文 | 0x041 | BCM上报 | 门锁 | BCM | 上位机 |

| 属性 | 内容 |
| ---- | ---- |

| 报文类型 | 事件触发 |
| 发送节点 | BCM |
| 接收节点 | 上位机 |
| 发送周期 | 无固定周期，故障产生或消除时即时发送 |

| 信号名称 | 起始位 | 长度(bit) | 分辨率/偏移量 | 物理范围 | 无效值 | 说明 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 故障码 | 0 | 8 | 1 / 0 | 0x01-0x04 | 0xFF | 0x01=传感器异常，0x02=CAN总线异常，0x03=车灯故障，0x04=车锁故障 |

### 4.2 BCM接收报文（上位机指令）

#### 4.2.1 灯光控制指令报文

| 属性 | 内容 |
| ---- | ---- |
| 报文ID | 0x011 |
| 报文名称 | 灯光控制指令报文 |
| 报文类型 | 事件触发（按需单次下发） |
| 发送节点 | 上位机 |
| 接收节点 | BCM |
| 发送周期 | 无固定周期，按需发送 |
| 数据长度（DLC） | 1 字节 |
| 指令最小间隔 | 100ms（两次相同指令之间的最小间隔，BCM做防抖处理） |

**信号布局表：**

| 信号名称 | 起始位 | 长度(bit) | 分辨率/偏移量 | 物理范围 | 无效值 | 说明 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 灯光控制指令 | 0 | 8 | 1 / 0 | 0x00-0x01 | 0xFF | 0x00=关闭近光灯，0x01=开启近光灯 |

**校验规则：**
- DLC必须为1，否则丢弃。
- 近光灯控制指令字段值必须为0x00或0x01，其他值视为非法，丢弃整帧报文。
- 100ms内重复收到相同指令值的报文，视为重复帧，丢弃不做处理。

**控制优先级：**
- CAN远程指令优先级高于本地按键指令。CAN指令与本地按键同时操作冲突时，执行CAN指令，丢弃按键指令。

## 5 通信时序规范

### 5.1 周期报文时序
| 报文名称 | 周期 | 容差 | 说明 |
| ---- | ---- | ---- | ---- |
| 设备心跳报文 | 2000ms | ±80ms | 计时器驱动，不受其他任务阻塞影响 |

### 5.2 事件报文时序

| 触发条件 | 最大延迟 | 说明 |
| ---- | ---- | ---- |
| 状态变化（车灯、门锁） | 20ms | 状态变化发生后到报文发出的最大延迟，含软件滤波与任务调度时间 |
| 故障产生/消除 | 50ms | 故障确认需经过防抖延时（如传感器异常需持续500ms才判定），确认后50ms内完成上报 |

### 5.3 指令响应时序

| 项目 | 时间 | 说明 |
| ---- | ---- | ---- |
| 指令接收确认 | ≤5ms | CAN中断接收后到协议解析完成的时间 |
| 指令执行完成 | ≤50ms | 从指令解析完成到IO输出、回读校验完毕的总时间（含执行器动作时间） |
| 状态报文反馈 | ≤100ms | 指令执行后，对应状态变化事件触发报文发出的最大延迟 |
| 指令最小间隔 | 100ms | 灯光/门锁指令防抖间隔，防止外部快速重复下发 |
| 故障清除最小间隔 | 500ms | 故障清除指令防抖间隔 |


## 6 总线异常处理机制

### 6.1 CAN错误状态分级

STM32F103的bxCAN外设具有三种错误状态，本系统对应处理策略如下：

| 错误状态 | 触发条件 | 系统响应 |
| ---- | ---- | ---- |
| 主动错误 | TEC<127 且 REC<127 | 正常通信，无额外处理 |
| 被动错误 | TEC≥127 或 REC≥127 | 继续通信，记录轻微故障 |
| 总线关闭 | TEC≥255 | CAN 外设自动离线，系统切入故障模式 |

### 6.2 Bus-Off自动恢复流程

CAN 外设进入 Bus-Off 状态后，硬件自动停止所有报文发送，仅保留接收能力。

系统软件检测到 Bus-Off 状态，立即执行以下恢复流程：
- 记录严重故障日志（故障码 = 0x02，CAN 总线异常）；
- 尝试发送故障状态报文；总线无法发送时故障信息存入本地故障缓存；
- 所有执行器输出强制安全状态（继电器断开）；
- 等待 100ms 后，完整重新初始化 bxCAN 外设，清除错误计数器；
- CAN 初始化完成后恢复通信；通信恢复成功，则上报【故障消除】报文；
- 最大重试次数：3 次；3 次恢复失败，持续保持故障安全模式，直到系统复位。

### 6.3 报文超时检测（上位机端）

本规范定义上位机对BCM的报文超时检测标准，BCM固件本身不做此检测，仅供调试上位机参考：

| 报文名称 | 超时阈值 | 超时处理 |
| ---- | ---- | ---- |
| 设备心跳报文 | 4000ms（两个周期） | 判定BCM离线，上位机告警 |
| 车灯状态报文 | 无超时（事件触发） | 不适用 |
| 门锁状态报文 | 无超时（事件触发） | 不适用 |
| 故障状态报文 | 无超时（事件触发） | 不适用 |

### 6.4 总线离线安全策略

CAN总线异常离线时，BCM自动执行以下安全策略：
- 所有继电器输出强制断开（RELAY_LIGHT=0，RELAY_LOCK=0）；
- RGB_RED常亮，RGB_GREEN、RGB_BLUE熄灭；
- BEEP按严重故障报警节奏鸣响；
- 保留本地按键控制功能（灯光、门锁、故障清除仍可操作）；
- 总线恢复后自动同步当前执行器状态。
