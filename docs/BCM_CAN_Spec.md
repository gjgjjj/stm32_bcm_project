## 1 文档说明

### 1.1 文档目的

本文档定义该模拟BCM车身控制器CAN通信协议的完整规范，包含物理层参数、报文定义、信号布局、通信时序与总线异常处理机制。所有CAN相关驱动开发、协议解析、上位机调试均以此文档为唯一依据。

### 1.2 适用范围

本文档适用于以下开发与调试场景：
- BCM固件中CAN驱动层、协议解析层代码开发
- CAN调试上位机的DBC文件制作与报文解析
- 系统集成测试中CAN通信功能验证

### 2.3 帧格式

本项目所有报文均采用**CAN 2.0A标准帧格式（11位ID）**。数据长度码（DLC）根据各报文实际信号长度定义，未使用字节填充0x00。


## 3 报文ID分配方案

### 3.1 ID编码规则

11位标准帧ID采用功能域划分方式编码，保障ID唯一性，避免总线仲裁冲突。

| 位段 | 位宽 | 编码含义 |
| ---- | ---- | ---- |
| Bit10 - Bit8 | 3位 | 报文类型：0=BCM上报报文，1=外部控制指令报文 |
| Bit7 - Bit5 | 3位 | 功能域：0=系统状态，1=灯光，2=门锁，3=故障诊断 |
| Bit4 - Bit0 | 5位 | 同功能域内报文序号|

## 5 通信时序规范

### 5.1 周期报文时序

| 报文名称 | 周期 | 容差 | 说明 |
| ---- | ---- | ---- | ---- |
| 设备心跳报文 | 1000ms | ±50ms | 计时器驱动，不受其他任务阻塞影响 |

### 5.2 事件报文时序

| 触发条件 | 最大延迟 | 说明 |
| ---- | ---- | ---- |
| 状态变化（车灯、门锁） | 20ms | 状态变化发生后到报文发出的最大延迟，含软件滤波与任务调度时间 |
| 故障产生/消除 | 50ms | 故障确认需经过防抖延时（如传感器异常需持续500ms才判定），确认后50ms内完成上报 |
| 执行器回读异常 | 20ms | 控制指令执行后立即回读，异常判定后20ms内完成上报 |

### 5.3 指令响应时序

| 项目 | 时间 | 说明 |
| ---- | ---- | ---- |
| 指令接收确认 | ≤5ms | CAN中断接收后到协议解析完成的时间 |
| 指令执行完成 | ≤50ms | 从指令解析完成到IO输出、回读校验完毕的总时间（含执行器动作时间） |
| 状态报文反馈 | ≤100ms | 指令执行后，对应状态变化事件触发报文发出的最大延迟 |
| 指令最小间隔 | 100ms | 灯光/门锁指令防抖间隔，防止外部快速重复下发 |
| 故障清除最小间隔 | 500ms | 故障清除指令防抖间隔 |

### 5.4 心跳超时判定

| 项目 | 值 | 说明 |
| ---- | ---- | ---- |
| 心跳发送周期 | 1000ms | BCM定时发送 |
| 外部节点超时阈值 | 3000ms | 连续3个周期未收到心跳报文 |
| 超时处理 | 判定BCM离线 | 上位机显示“BCM离线”告警 |


## 6 信号数据范围与校验规则

### 6.1 通用校验规则

BCM接收外部指令报文时，执行以下逐层校验，任一不通过即丢弃整帧报文：

1. **DLC校验**：实际接收的DLC必须与报文定义一致，DLC不符则丢弃。
2. **信号范围校验**：各信号字段值必须在定义的物理范围内，超范围则丢弃。
3. **保留字段校验**：保留字段不强制校验，但发送方必须填充0x00。

### 6.2 信号无效值汇总

| 信号名称 | 所属报文 | 无效值 | 含义 |
| ---- | ---- | ---- | ---- |
| BCM工作状态 | 设备心跳报文 | 0xFF | 状态未知/异常 |
| ADC采集电压 | 设备心跳报文 | 0xFFFF | 采集异常/超量程 |
| 近光灯状态 | 车灯状态报文 | 0x03 | 状态未知 |
| 门锁状态 | 门锁状态报文 | 0x03 | 状态未知 |
| 故障码 | 故障状态报文 | 0xFF | 无效故障码 |
| 故障等级 | 故障状态报文 | 0x03 | 无效等级 |
| 故障事件 | 故障状态报文 | 0x03 | 无效事件 |
| 当前故障数量 | 故障状态报文 | 0x0F | 无效数量 |

### 6.3 非法报文丢弃处理

所有校验不通过而丢弃的报文，不响应、不执行、不回复，仅记录丢弃计数（用于调试统计，可选输出串口日志）。连续收到非法报文不触发系统级故障。


## 7 总线异常处理机制

### 7.1 CAN错误状态分级

STM32F103的bxCAN外设具有三种错误状态，本系统对应处理策略如下：

| 错误状态 | 触发条件 | 系统响应 |
| ---- | ---- | ---- |
| 主动错误 | TEC<96 且 REC<96 | 正常通信，无额外处理 |
| 被动错误 | TEC≥96 或 REC≥96 | 继续通信，记录轻微故障，蓝灯快闪提示 |
| 总线关闭（Bus-Off） | TEC≥256 | CAN外设自动离线，系统切入故障安全模式 |

### 7.2 Bus-Off自动恢复流程

1. CAN外设进入Bus-Off状态后，硬件自动停止发送，仅可接收。
2. 系统软件检测到Bus-Off状态，立即执行以下恢复流程：
   - 记录严重故障日志（故障码=0x02，CAN总线异常）；
   - 发送故障状态报文（故障事件=故障产生），若总线已无法发送则写入待发送队列；
   - 所有执行器输出强制安全状态（继电器断开）；
   - 延时100ms后，软件请求CAN外设退出Bus-Off状态，重新初始化CAN模块；
   - CAN初始化成功后，尝试恢复正常通信，发送故障状态报文（故障事件=故障消除）；
   - 恢复成功，退出故障安全模式；恢复失败，保持故障安全模式。
3. 最大重试次数：3次。3次恢复失败后，保持故障安全模式直至系统复位或人工干预。

### 7.3 报文超时检测（外部节点侧）

本规范定义外部节点对BCM的报文超时检测标准，BCM固件本身不做此检测，仅供调试上位机参考：

| 报文名称 | 超时阈值 | 超时处理 |
| ---- | ---- | ---- |
| 设备心跳报文 | 3000ms（3个周期） | 判定BCM离线，上位机告警 |
| 车灯状态报文 | 无超时（事件触发） | 不适用 |
| 门锁状态报文 | 无超时（事件触发） | 不适用 |
| 故障状态报文 | 无超时（事件触发） | 不适用 |

### 7.4 总线离线安全策略

CAN总线异常离线时，BCM自动执行以下安全策略：
- 所有继电器输出强制断开（RELAY_LIGHT=0，RELAY_LOCK=0）；
- RGB_RED常亮，RGB_GREEN、RGB_BLUE熄灭；
- BEEP按严重故障报警节奏鸣响；
- 保留本地按键控制功能（灯光、门锁、故障清除仍可操作）；
- 总线恢复后自动同步当前执行器状态。


## 8 DBC文件说明

### 8.1 DBC文件概述

| 项目 | 内容 |
| ---- | ---- |
| DBC文件名称 | BCM_Controller.dbc |
| 适用标准 | CAN 2.0A 标准帧（11位ID） |
| 包含内容 | 全部7条报文定义、所有信号布局、无效值、注释信息 |
| 字节序 | Intel（小端） |
| 波特率 | 250 Kbps |

### 8.2 DBC文件使用说明

1. 将 `BCM_Controller.dbc` 文件导入CAN调试上位机。
2. 确认上位机CAN参数配置为：250Kbps、标准帧、采样点80%。
3. 加载DBC后，接收到的报文将自动解析为物理值并在界面显示。
4. DBC文件随项目源码一并交付，纳入Git版本管理。
