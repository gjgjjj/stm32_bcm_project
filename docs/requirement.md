## 1 概述
&emsp;&emsp;本项目为嵌入式车载车身控制器原型开发项目，以民用乘用车车身域控制功能为参照，基于MCU+RTOS架构实现轻量化BCM核心功能。项目采用**四层软件分层架构 + HAL 底层**，层级单向自上而下调用，禁止跨层逆向调用，聚焦嵌入式实时开发、CAN 总线应用、车载故障诊断、系统可靠性设计，为车载 ECU 开发实战项目。

&emsp;&emsp;本产品为技术验证原型设备，非车用量产设备，不满足汽车功能安全量产标准，仅用于技术学习与工程验证。

## 2 系统总体需求
系统采用四层软件分层架构，完整依赖链：**应用层 → 服务层 → OSAL 操作系统抽象层 → 驱动层 (BSP) → HAL 库 → 硬件**。层级仅允许自上而下单向调用，禁止跨层、越级、逆向调用。
1. **应用层**：负责车身业务策略、任务 / 定时器 / 内核对象创建仅允许`system_manager`模块调用 OSAL 接口；其余业务模块只调用服务层接口，禁止直接访问 OSAL、BSP、HAL。实现灯光、门锁、迎宾灯光、BCM 全局状态、故障联动业务逻辑。
2. **服务层**：提供通用基础组件：按键管理、信号滤波、执行器诊断、看门狗服务、CAN 协议解析、存储管理、日志服务；全部多任务同步原语均调用 OSAL 接口，**禁止直接调用 FreeRTOS 原生 API，禁止业务逻辑**。
3. **OSAL 操作系统抽象层**：收拢全部 FreeRTOS 原生 API，封装任务、互斥锁、消息队列、软件定时器、系统时间延时接口；上层只使用 osal.h，不直接包含 FreeRTOS 头文件。更换 RTOS 只需修改 OSAL 内部实现，上层业务无需改动。
4. **驱动层**：纯硬件外设封装，只做硬件读写；**禁止 RTOS、队列、互斥锁、业务判断逻辑**；硬件中断仅做数据拷贝，中断内不调用 OSAL 阻塞接口。

系统运行模式分为两类：
- **正常模式**：上电自检通过后进入，所有功能正常运行，支持本地控制与远程总线控制。
- **故障模式**：自检失败、CAN 严重故障触发；切断执行器输出，声光告警；保留本地按键、故障清除能力。

## 3 功能需求
### 3.1 本地按键控制功能
设备支持两路本地按键实现手动控制：
1. KEY1（PA0）：短按切换车灯开关状态；**长按 1000ms 切换灯光手动 / 自动模式**。
2. KEY2（PC13）：短按切换门锁上锁 / 解锁；**长按 1000ms 清除 Flash 全部历史故障记录**。

- 按键采用状态机软件防抖，消抖时间**20ms**，长按判定阈值 1000ms；区分短按、长按事件，输出按键事件队列。
- 控制优先级：**远程 CAN 指令 = 本地按键 ＞ 迎宾自动灯光逻辑**；按键、CAN 指令可以直接抢占覆盖迎宾灯光状态。

### 3.2 传感器信号采集功能
ADC1_IN11 (PC1) 采集环境光模拟传感器原始数据；服务层信号滤波模块完成 N 点滑动平均滤波；采用双阈值滞回判定昼夜状态：

- 黑夜：ADC＜1600；
- 白天：ADC＞2800；
- 中间区间保持上一次昼夜状态。
- ADC 采样超量程判定传感器异常；连续多次异常上报传感器故障；异常时保持上一次有效昼夜状态，不执行自动迎宾逻辑。
- BSP 驱动只输出原始 ADC 采样值，滤波、滞回、异常判定全部在服务层实现。

### 3.3 车身执行器控制功能
&emsp;&emsp;通过外接两路继电器模块分别模拟近光灯、门锁执行器负载，实现开关控制功能。系统增加执行器互锁保护，杜绝逻辑冲突动作同时执行。
&emsp;&emsp;每条控制指令下发后，延时稳定时间读取继电器触点回读引脚，校验继电器实际触点状态；采集结果经过 20ms 软件防抖，**持续检测到指令目标状态与回读实际状态不一致时，判定对应执行器故障（灯光故障码 0x03、门锁故障码 0x04），记录故障信息并上报 CAN 故障报文。**

### 3.4 灯光控制功能及迎宾灯功能
- 灯光具备手动模式、自动模式；KEY1 长按切换模式。
- 手动模式：灯光仅响应 CAN 指令、本地 KEY1 短按。
- 自动模式：解锁事件满足全部条件（解锁事件 + 夜间状态 + 灯光关闭），自动触发迎宾灯光；点亮车灯并开始计时。
- 迎宾运行条件：灯光自动模式、夜间状态、当前灯光关闭；迎宾运行期间再次收到解锁事件直接忽略。
- 迎宾期间，CAN 指令、本地按键具备高优先级，可直接终止迎宾并接管灯光输出；切换为手动模式同样终止迎宾。
- 迎宾计时到达配置时长自动关闭灯光，结束迎宾时序。

### 3.5 CAN总线通信功能
&emsp;&emsp;设备基于板载CAN外设实现标准车载CAN2.0通信，支持周期状态上报、远程指令接收功能。通信具备完整闭环机制，接收远程控制指令执行完成后，上报执行器最新状态报文反馈执行结果，反馈指令执行结果。所有接收信号进行合法范围校验，非法报文直接丢弃。
总线报文包含：BCM 执行器状态、故障信息、远程控制指令。

&emsp;&emsp;系统具备完整总线异常处理能力，支持报文超时检测、CAN硬件错误状态识别与自动恢复。总线异常离线后，设备自动切入安全控制状态，防止执行器失控。

### 3.6 故障诊断与管理功能
&emsp;&emsp;系统内置完整故障诊断体系，对传感器异常、CAN总线异常等故障进行识别、分级、上报与存储。故障分为普通故障与严重故障两个等级，不同等级故障对应差异化的声光报警与功能限制策略。

&emsp;&emsp;定义标准化故障恢复逻辑，区分自恢复故障与人工清除故障。所有故障信息包含故障码，通过SPI Flash实现掉电持久化存储，支持上电自动读取历史故障记录。存储数据增加校验机制，防止数据损坏异常。
&emsp;&emsp;支持通过串口调试接口查询、打印全部历史故障日志；支持 KEY2 长按清除存储故障。

### 3.7 系统可靠性基础功能
1. **独立看门狗 IWDG**：硬件溢出时间约 2s；**BSP 层只提供喂狗接口，业务任务禁止直接调用喂狗**。
2. **多任务心跳监控（IWDG 服务）**
   - 被监控任务：故障监控、输入采集、BCM 控制、系统管理 4 个非阻塞任务；任务周期调用`IWDG_Service_TaskFeed()`上报心跳。
   - 阻塞任务（CAN 协议任务、故障处理任务）**不纳入看门狗心跳监控**，阻塞不会触发复位。
   - 系统管理任务**50ms 周期调用巡检函数**；全部被监控任务正常才调用 BSP 喂狗；任一任务停止上报心跳则停止喂狗，等待 IWDG 硬件复位。
   - 心跳计数数组使用 OSAL 互斥锁保护，锁超时 10ms，拿锁失败直接放弃本次操作。
3. **上电自检**：上电完成时钟、GPIO、ADC、CAN、UART、SPI‑Flash 外设自检；自检失败直接进入故障模式。
4. **共享资源保护需求**：全部多任务共享资源必须使用 OSAL 静态互斥锁保护，禁止裸读写全局共享变量。需要保护资源清单：
   - BCM 全局状态结构体；
   - 应用层活跃故障表；
   - 看门狗任务心跳计数数组；
   - CAN 发送接口；
   - SPI‑Flash / SPI 总线；
   - 串口日志打印输出。

### 3.8 数据存储功能
&emsp;&emsp;通过SPI W25Q64 Flash存储故障日志，采用线性追加存储机制，均衡读写寿命，实现故障记录循环存储。

### 3.9 日志调试功能

- USART1（PA9 TX、PA10 RX）波特率 115200；串口日志分为 DEBUG、INFO、ERROR 三个等级，支持全局宏关闭调试日志；
- 多任务打印输出必须加 OSAL 互斥锁，防止日志乱码；
- BSP 单元测试模块为调试辅助模块，用于验证 BSP 驱动，运行完成自动销毁测试任务，不参与业务运行。

## 4 非功能性需求
### 4.1 实时性需求
FreeRTOS 抢占式调度，任务按优先级分配；CAN 协议任务优先级最高；软件定时器用于周期心跳报文，时序不受任务阻塞影响。

### 4.2 可靠性需求
独立看门狗 + 任务心跳监控双重防护；故障防抖、触点回读校验；Flash 记录校验和；共享资源互斥锁保护；总线异常自动恢复。

### 4.3 可维护性需求
分层模块化；OSAL 隔离 RTOS；日志分级输出；故障可追溯；BSP 单元测试辅助底层驱动验证。

### 4.4 可扩展性需求
四层架构低耦合；新增车身功能只修改应用层、服务层；更换 RTOS 仅修改 OSAL；硬件引脚修改只改动 BSP 驱动层。

### 4.5 资源约束需求
适配 STM32F103ZET6 RAM/Flash；软件定时器上电一次性创建，不动态删除；定时器内部包装结构体属于常驻堆内存。

## 5 接口需求
### 5.1 硬件 IO 接口
按键、继电器输出、四路触点回读、蜂鸣器、RGB 指示灯、ADC 光照采集，全部硬件操作封装在 BSP，上层业务不直接操作寄存器。

### 5.2 CAN 通信接口
周期报文、远程指令报文、状态反馈报文、故障报文；报文 ID、信号定义、时序约束参考配套文档《CAN 通信协议规范》。

### 5.3 调试接口
USART1 串口日志输出；SWD 下载调试接口；BSP 单元测试用于驱动验证。

### 5.4 存储接口
SPI‑Flash 故障日志读写接口，由 storage_manager 服务层封装。

## 6 测试需求
### 6.1 单元测试
- 服务层单元：按键状态机、信号滤波、故障防抖判定、校验和算法。
- BSP 单元测试模块：GPIO、ADC、UART、SPI‑Flash、CAN 回环测试，包含正常用例与非法入参边界测试，测试完成自动销毁测试任务。

### 6.2 集成测试
灯光 / 门锁控制、迎宾灯光、故障告警、Flash 故障持久化、看门狗任务心跳监控整机联调。

### 6.3 CAN 总线测试
指令闭环应答、周期报文时序、Bus‑Off 故障恢复、时序指标验证。

### 6.4 异常注入测试
模拟继电器粘连、传感器异常、任务卡死、CAN 总线断开、多任务并发资源竞争、掉电半写 Flash。

## 8 风险与约束
1. 本项目为技术原型设备，**非实车量产设备，不满足 ISO26262 功能安全标准，禁止直接用于实车**。
2. MCU 为 STM32F103ZET6，算力、RAM/Flash 资源有限，不实现复杂车载高级功能。
3. 仅支持 CAN2.0A 标准帧，不支持 CAN‑FD、LIN。
4. 故障诊断为原型软件模拟实现，无专业车载诊断硬件电路。
